# DECISION_LOG.md — Council debate & resolutions

| # | Issue | Positions | Trade-offs | Decision | Reason |
|---|-------|-----------|-----------|----------|--------|
| 1 | **Convenience vs student privacy** (teacher-held keys, browser → provider) | M3: proxy-only, no browser keys. M4/M1: teachers need a zero-infrastructure pilot; a proxy kills adoption. | Proxy = admin control + audit but requires IT project; browser keys = instant but key custody on teachers. | Browser keys stay **for the pilot** with: session-only storage by default, explicit remember opt-in, clear control, HTTPS+allowlist endpoints, consent dialog naming the destination on every send. Proxy documented as the production architecture (ARCHITECTURE.md) and required for any beyond-pilot rollout. | Pilot viability requires the direct path; the added controls close the acute risks (persistence, exfiltration, silent sends). |
| 2 | **Single-file simplicity vs maintainability** | M5: split the JS into modules now. M7: a large refactor mid-safety-pass is how regressions ship. | Refactor improves testability; but P0 is safety, and the source is already modular Python — only the embedded JS is monolithic. | Keep the current build (Python modules → compiled HTML) for this pass; JS extraction to `webapp/*.js` with node unit tests is P1. `dist/markable.html` build task added now. | "Prefer a working, tested P0 implementation over a large speculative redesign" (brief). The monolith is the artifact, not the source. |
| 3 | **Automatic marking vs teacher control** | M2: auto-accept high-confidence items to save time. M1: every flagged item needs a human; unflagged items are still teacher-owned proposals. | Full review of everything is slow; auto-accept risks false auto-approval. | Deterministic flags (bounds, confidence < 0.85, blanks, duplicates, model flag) force review; unflagged items export as `auto-accepted` **labelled as such** in the audit CSV; export locked until all flagged items are decided. No silent finalisation anywhere. | Matches non-negotiable #1 and #7; false auto-approval rate becomes a measured metric in the eval plan before any threshold is relaxed. |
| 4 | **Automated curriculum mapping vs validity** | M6: label-overlap mapping is too weak to show teachers. M1/M4: even suggested mappings help teachers orient, if honestly labelled. | Hiding mappings loses value; showing them unlabelled overclaims. | Keep browser mappings, permanently labelled **SUGGESTED MAPPING**; confirmed state requires the CLI teacher map (`tag --map`). Four-state model (confirmed/suggested/ambiguous/unmapped) is P1. | Honest labelling converts a validity risk into a drafting aid. |
| 5 | **Model quality vs cost** | M2: tiered models (cheap transcription, strong judging). M5: one configurable model constant now; tiers later. | Tiering cuts cost but multiplies eval surface before any gold-dataset baseline exists. | Single strong model (`AI_MODELS.claude = claude-opus-4-8`), centralised and configurable. Tiered strategy + adjudication designed in AI_MARKING_EVALUATION_PLAN.md, gated on baseline eval results. | Measure one pipeline before optimising two. |
| 6 | **Preserving original formatting vs simplifying imports** | M7: regex DOCX parsing loses tables/equations silently — block those files. M4: blocking every real-world DOCX kills the tool. | Full-fidelity DOCX parsing in-browser is a large dependency; blocking is hostile. | Import proceeds **with a visible honest-extraction warning** counting tables/images/equations not extracted, on every consumer of `docText`. Maintained parser bundling is P1. | No silent corruption (non-negotiable #6) without destroying usability. |
| 7 | **Same-name students** | M6: block import until resolved. M4: teachers can't always fix the workbook at upload time. | Blocking is safest; but the data is still analysable if identities are kept separate. | Never merge: same-name students are kept separate, disambiguated with their ID (or row number), and a blocking-style warning banner tops the dashboard until the workbook is fixed. | Preserves analysis while making the hazard impossible to miss. |
| 8 | **Answer markers in the optimiser format** | M1: remove the `*` convention entirely. M5: the `*` is what `markable ingest` uses to build the key — removing it breaks the pipeline. | Format change vs leakage risk. | Keep `*` in the **teacher master only**; student exports strip markers and pass a leak detector that blocks on any residue; files are loudly labelled. | Preserves the ingest contract and closes the leak with a defence-in-depth gate. |
